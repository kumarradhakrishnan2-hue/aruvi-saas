ARUVI — ENGLISH ASSESSMENT CONSTITUTION · PREPARATORY · VERSION 1.5
Stage: Preparatory (Grades III–V)

================================================================================
DESIGN PRINCIPLE
================================================================================

The English LP → Assessment arc has two phases:

  LP          → selects priority tasks, enacts them in class, and
                writes ONE spine-cell `implied_lo` per (section × spine)
                cell that was taught.
  Assessment  → reads the LP handoff and the section's text summary
                from the chapter summary. It generates a PAIR of original
                items per spine-cell implied_lo, grounded entirely in
                that section's own content.

WHY A PAIR AND NOT ONE (v1.4). A spine-cell's `implied_lo` is a broad
observable outcome, and the LP teaches that one cell across several units.
One item under-samples it. The pair samples the cell twice — once to check
the child recognises it, once to have her produce it — so the teacher gets a
usable check partway through the cell and a short production when it closes.
At preparatory the pair is SMALL by design: two brief items, never two long
tasks, and never two written tasks where one can be oral.

THE ASSESSMENT GENERATOR DOES NOT READ `tasks_verbatim[]` OR
`question_bank[]` FROM THE SUMMARY. Items are derived from the
section's text-summary fields, not from the textbook exercise
wording. The one narrow exception is listening items in the oracy
spine — see INPUTS below.

The 5 prep-native spines (reading, oracy, writing,
word_work, beyond_text) carry NCF compliance
through the static spine→CG lookup. C-codes do not appear anywhere
in the assessment JSON.


================================================================================
INPUTS
================================================================================

1. LP JSON → `coverage_handoff`, keyed by the 5 prep spines, each
   carrying `section_contributions[]`. Each contribution is a
   (section × spine) cell with at least one anchored task, providing:
     - `section_id`, `section_title`, `section_type`
     - `implied_lo`       drives question type and cognitive demand
     - `section_context`  drives what the question is specifically about
     - `tasks_anchored[]` LP audit only — NOT READ by the generator
   This is the primary driver of item generation.

2. Summary JSON → per main_section, the content sources are:
     - `prose_summary`            prose / narrative / dialogue / informational
     - `poem_text` + `poem_appreciation_summary`  poem
     - `picture_story_summary` + `dialogue_text`  picture_narrative
   These are the ONLY content sources for generated items.

   The generator MUST NOT read `tasks_verbatim[]` or `question_bank[]`
   from the summary.

   NARROW CARVE-OUT — listening tasks inside oracy:
   When generating or verifying a listening-type oracy item, the
   generator MAY read `transcript_ref` and `transcript_text` from the
   relevant task object inside the section's `oracy` cell. No other
   field of any `tasks_verbatim[]` entry is readable.


================================================================================
OUTPUT
================================================================================

Assessment JSON per chapter: header + spine-keyed sections. Only
spines with at least one `section_contribution` in the LP handoff
appear. Each spine section is a flat array of items ordered by
`section_id` (A before B before C).


================================================================================
RULE 1 | PRESENT SPINES ONLY
================================================================================

Emit only spines that have at least one `section_contribution` in
the LP handoff. A spine with zero contributions is OMITTED entirely
— no note, no placeholder.

Present spines are emitted in this fixed order (skip absent ones):
  reading · oracy · writing · word_work · beyond_text

Within each spine, items are ordered by `section_id` (A → B → C).


================================================================================
RULE 2 | TWO ITEMS PER SPINE-CELL IMPLIED LO
================================================================================

For each `section_contribution` in the handoff, generate exactly TWO
assessment items — a PAIR, emitted in slot order. `implied_lo` determines
question type and cognitive demand; `section_context` determines what the
question is about. Neither alone is sufficient. Both items of a pair carry
the SAME `source_lo` and `source_context` (Rule 8): they sample one outcome
twice, they do not split it into two outcomes.

THE PAIR MUST DIFFER ON BOTH AXES:

  DEMAND — SLOT 1 is RECOGNITION: the child picks, matches, judges or
     completes. SLOT 2 is PRODUCTION: the child says or writes something
     short of her own. Slot 2 is ALWAYS the higher of the two; a pair at one
     rung is non-compliant.

  TYPE — the two items MUST NOT share a `question_type`.

SLOT TABLE (prescriptive — the type is set by the slot, not chosen freely;
types are drawn from Rule 4's per-spine permitted sets and this table never
widens them):

  Spine        | SLOT 1 — recognition          | SLOT 2 — short production
  -------------|-------------------------------|---------------------------------
  reading      | MCQ · TRUE_FALSE · MATCH      | SCR — 1–3 sentences (why / how /
               |                               | what would you)
  oracy        | MCQ · TRUE_FALSE — listen-    | ORAL_PROMPT — retell, describe,
               | and-judge, sound              | share
               | discrimination                |
  writing      | SCR — guided single sentence  | WRITING_TASK — short-form, rubric
               | or caption                    |
  word_work    | FILL_IN · MATCH               | SCR — use the word in a sentence ·
               |                               | ORAL_PROMPT — blend-and-say,
               |                               | sight-word read-aloud
  beyond_text  | MATCH                         | PROJECT · ORAL_PROMPT — riddle,
               |                               | share-out

KEEP THE PAIR LIGHT. Two brief items. Where both slots could be written,
prefer an oral slot 2 — at this stage speaking is the cheaper demonstration
and the more honest one. Never pair two WRITING_TASKs; never pair two items
that each need a table.

Constraints (both items):
  a) The item MUST be grounded strictly in the section's content
     source (per INPUTS §2). No outside content.
  b) The item MUST be original — must not reproduce, paraphrase, or
     structurally echo any textbook exercise wording.
  c) The item MUST directly test the `implied_lo` — not a generic
     comprehension question, not a tangentially related exercise. Where the
     `implied_lo` is compound, the two items MUST take different strands of it.
  d) Question type is drawn from the slot table above.
  e) ECR is BANNED at preparatory (Rule 4) — in either slot.

ORDER. Within a spine's flat array, items are ordered by `section_id`
(Rule 1), and WITHIN a contribution slot 1 precedes slot 2. This authoring
order IS the teaching order (Rule 8A) and the platform relies on it; never
emit slot 2 first, and never interleave two contributions' items.

There is no fallback path: a spine cell with no contribution
produces no items — not one, not two. A pair is never broken: a contribution
yields two items or none. Item count per chapter = 2 × total
`section_contributions` across all spines in the handoff.


================================================================================
RULE 3 | RICHNESS — GROUND ITEMS IN SECTION CONTENT
================================================================================

Every item must be visibly anchored in the section's actual content.
Generic questions usable across any chapter are prohibited.

Required — items must draw on at least ONE of:
  - A named character, speaker, or person from the section.
  - A specific event, scene, or episode from `prose_summary` or
    `picture_story_summary`.
  - A specific image, sound-pattern or phrase in the poem — ADDRESSED
    BY ITS PLACE, NOT COPIED OUT: a stanza or line reference plus
    an incipit of AT MOST EIGHT WORDS in double quotes — e.g.
    Read the lines on page 42 beginning "The mighty mountains stand".
  - A speech-bubble line from `dialogue_text` (picture_narrative).
  - The vocabulary, phonics, or grammar concept as it appears in the
    section (for word_work items: the concept
    MUST be named explicitly in the stem — e.g. "consonant blend
    'gr'", "action words", "compound words").
  - A specific writing prompt or communicative context from the
    section's theme.

Prohibited:
  - Stems answerable without reading the section.
  - Stems recycled from textbook exercise wording.
  - REPRODUCING THE POEM. A poem's lines are not copied into
    `item_stem`, `visual_stimulus`, `suggested_answer` or any rubric
    field — beyond the eight-word incipit that locates them, and never
    with an ellipsis continuing the quotation. The child is holding the
    book; the poem lives there, exactly as a textbook picture does
    (Rule 9).
  - Phonics or vocabulary items that test a concept in isolation
    without grounding in the section's language.


================================================================================
RULE 4 | QUESTION TYPE
================================================================================

Permitted `question_type` values at preparatory:

  MCQ           Multiple Choice (4 options, exactly one correct)
  SCR           Short Constructed Response (1–3 sentences)
  MATCH         Matching (Column 1 ↔ Column 2)
  FILL_IN       Blanks in a cloze set; at most ONE visual (Rule 9); multi-part
                A/B allowed ONLY if every part is textual (no visual)
  TRUE_FALSE    True / False (with optional justification)
  ORAL_PROMPT   Speaking / listening task with rubric
  WRITING_TASK  Short-form writing task with rubric
  PROJECT       Beyond-text project / hands-on extension

ECR is BANNED at preparatory. Long-form writing is short-form
`WRITING_TASK` (rubric) or `SCR` (1–3 sentences). Emitting
`question_type: "ECR"` is a constitution violation.

Default mapping by spine — pick the type that best fits the
`implied_lo`:

  reading                       → MCQ · SCR · TRUE_FALSE · FILL_IN · MATCH
  oracy                         → ORAL_PROMPT (default) ·
                                  SCR (short written response to a
                                  listening prompt) ·
                                  MCQ / TRUE_FALSE (sound discrimination,
                                  listen-and-judge)
  writing                       → WRITING_TASK · SCR
  word_work  → FILL_IN · MATCH · MCQ · TRUE_FALSE ·
                                  ORAL_PROMPT (phonics drill, blend-and-say,
                                  sight-word read-aloud)
  beyond_text                   → PROJECT · ORAL_PROMPT (riddles,
                                  share-out) · MATCH

TRUE_FALSE vs MCQ disambiguation:
  TRUE_FALSE — every option is a complete declarative sentence the
               student must judge true/false. `options[]` carries
               `is_correct` per statement.
  MCQ        — exactly one option is correct and the options are NOT
               full declarative sentences being judged for truth
               (e.g. "Choose the correct meaning of…"). `options[]`
               flags the one correct entry; `suggested_answer` is
               omitted.

Do NOT classify "select the true statements" tasks as MCQ.

MCQ OPTION ORDER IS NOT YOURS TO SET. Emit the four options in whatever
order they were authored; order carries no meaning. Uneven letters across a
chapter are coincidence, not a defect, and correcting them is not your job —
the platform arranges options deterministically after generation.

An option MUST NOT refer to another option by its label: no "both A and B",
"none of the above", "all of the above", "either B or C". Those are the one
construction a downstream arrangement cannot reorder without rewriting the
item.


================================================================================
RULE 5 | ANSWER LAYER — CLOSED VS OPEN
================================================================================

Each item is CLOSED or OPEN by its `question_type`:

  CLOSED  →  MCQ · FILL_IN · MATCH · TRUE_FALSE · SCR (when factual)
  OPEN    →  ORAL_PROMPT · WRITING_TASK · PROJECT · SCR (when reflective)

CLOSED items carry `teacher_guide.suggested_answer` with type-specific
rules:
  MCQ           — `suggested_answer` MUST be "" (the correct option is
                  already marked `is_correct: true` in `options[]` and
                  highlighted visually for the teacher; do not repeat it).
                  Instead, populate `teacher_guide.what_each_option_reveals`
                  — a keyed object with ONE entry per INCORRECT option,
                  keyed to that option's `label` in `options[]`, each value
                  a single sentence explaining what misconception a student
                  who chose it likely holds. Omit the correct option; do NOT
                  use `note` for distractor analysis (`note` is reserved for
                  the verification-failure fallback only).
                  Example what_each_option_reveals: {
                    "A": "Students who choose this may conflate friendship with material giving.",
                    "C": "Reveals a literal reading that misses the poem's invitation to empathy.",
                    "D": "Suggests the student has reversed the poem's logic." }
  MATCH         — the matched pairs as a STRUCTURED `answer_key`: an array
                  of { "left", "right" } objects, one per pair — `left` =
                  the Column A / left-hand entry (its text, matching the
                  visual_stimulus table), `right` = its correct Column B
                  match (for an ordering task, `right` = the position
                  number). ALSO give a short `suggested_answer` string
                  ("1-c, 2-a, 3-b") as a fallback. The app renders
                  `answer_key` as rows, so it MUST be machine-parseable
                  pairs — NEVER a prose paragraph or pairs with inline
                  glosses.
  FILL_IN       — each blank's answer, numbered to its blank.
  TRUE_FALSE    — verdicts plus a one-sentence justification from the
                  source text.
  SCR (factual) — verified answer in 1–2 sentences.Where deterministic answer like order asked, only order to be given.

OPEN items carry `teacher_guide.expected_elements` — 3 bullets,
each ≤ 8 words (Rule 11).

OPEN items MUST NOT carry `suggested_answer`.
CLOSED items MUST NOT carry `expected_elements`.


================================================================================
RULE 6 | ANSWER VERIFICATION
================================================================================

For every CLOSED item, verify the answer against the section's content
source:
  - prose / narrative / dialogue / informational → `prose_summary`
  - poem                                         → `poem_text` +
                                                   `poem_appreciation_summary`
  - picture_narrative                            → `picture_story_summary` +
                                                   `dialogue_text`

For oracy items that are listening-based (carry a `transcript_ref`):
verify against `transcript_text` from the relevant task object in
the section's `oracy` cell (the one allowed read of a tasks_verbatim
sub-field, per INPUTS §2 carve-out).

Set `verified: true` only if the answer is unambiguously supported by
the source.

For OPEN items: `verified` is always `true` (rubrics are not solved).

If a closed item's answer cannot be verified, Rule 7 applies.


================================================================================
RULE 7 | FALLBACK (VERIFICATION FAILURE)
================================================================================

When a closed item's answer cannot be verified:

  - `item_stem`                       = ""
  - `verified`                        = false
  - `teacher_guide.suggested_answer`  = ""
  - `teacher_guide.note`              = "[Verification failed]
    Refer to the section text for <spine> content in <section_title>."

The fallback item is still emitted (not silently dropped) so the
teacher sees the gap and can substitute.


================================================================================
RULE 8 | SOURCE TAGGING
================================================================================

Every item carries:

  - `source_section_id`     A | B | C ...
  - `source_section_title`  copied verbatim
  - `source_section_type`   poem | prose | narrative | dialogue |
                            informational | picture_narrative
  - `source_spine`          reading | oracy | writing |
                            word_work | beyond_text
  - `source_lo`             the spine-cell `implied_lo` from the LP
                            handoff, copied verbatim
  - `source_context`        the `section_context` from the LP handoff,
                            copied verbatim


================================================================================
RULE 8A | ITEM ANCHORING — THE CELL IS THE ANCHOR, AND IT IS NOT YOURS TO NUMBER
================================================================================

An item's anchor is the (section × spine) CELL it was generated from, carried
by the two Rule 8 fields it already has: `source_section_id` and
`source_spine`, both copied verbatim from the handoff contribution consumed.
Together they ARE the anchor — there is no third field to emit.

The platform resolves that cell to the unit(s) that taught it by matching the
pair against each period's own `section_id` + `spines_taught[]`.

TWO-STAGE SCOPING (v1.4, and the reason the pair is ORDERED). Where a cell is
taught across several units, its two items do NOT both wait for the cell to
close. Rule 2's slot table makes the pair genuinely stage-able:

  SLOT 1 is scoped to the cell's EARLY teaching — the recognition item is
     answerable once the strand it names has been taught, not once the whole
     cell has.
  SLOT 2 is scoped to the cell's COMPLETION — the production item presumes
     the whole cell.

The platform therefore DISPERSES a cell's items across the units that taught
it, in slot order, and slot 2 lands at or near the close. This is why Rule 2
forbids emitting slot 2 first: the order you author is the order the platform
deals them.

Author each item so it is honest at its own stage. A slot-1 item that silently
depends on the cell's last unit is the defect this rule exists to prevent —
it will be shown to the teacher partway through the cell.

MUST NOT emit `period_ref`, `period_number`, `unit_ref`, or any other unit
number or position. Scoping is declared by SLOT, never by number: which units
a cell occupies, and how many, is decided long after this file is written, and
declaring the link would freeze an arrangement the platform varies.


================================================================================
RULE 9 | VISUAL STIMULUS
================================================================================

`visual_stimulus` is a STRING. Permitted formats at preparatory:

  ""                            no stimulus (default for most items)

  Pipe-delimited table          2+ lines, every line contains "|",
                                first row is header. Used for MATCH
                                items and tabular comprehension built
                                from the source text.

For items grounded in a textbook picture (picture_narrative sections,
picture-prompted writing, oral observation prompts), do NOT introduce
a separate visual format. Instead, reference the textbook page in
`item_stem` itself — e.g. "Look at the picture on Textbook page 6
and write what each character is doing." The teacher has the book;
the image lives there.

Prohibited: inline SVG, ASCII art, image markup, base64 image,
external image reference, italic prose specs.

MATCH items with a pipe-table `visual_stimulus`: `item_stem` carries
ONLY the task instruction (e.g. "Match each animal with its young
one."). The column contents are entirely in `visual_stimulus`. Do
NOT repeat the column entries in `item_stem`.

FILL_IN items with a pipe-table `visual_stimulus`: the SAME rule
applies. `item_stem` carries ONLY the task instruction; the table —
header row and every data/blank row — lives entirely in
`visual_stimulus`. Do NOT reproduce the table as pipe-markdown, plain
text, or a paraphrased list in `item_stem`. A FILL_IN item owns at
most ONE `visual_stimulus`. It MAY carry multiple parts (A/B) ONLY if
every part is textual/prose; any part that would need its own table or
visual must be split into a separate item.

MCQ / TRUE_FALSE: the choices live ONLY in `options[]`. `item_stem`
carries only the question or task instruction — do NOT inline, letter,
or repeat the option texts (no "A. … B. …" block) in the stem.

Structural fidelity:
  - Multi-line stems (TRUE_FALSE statement lists only, NOT MCQ
    options) — reproduce each line separately, do NOT collapse into
    prose.
  - Tabular structures — render as pipe-delimited table in
    `visual_stimulus`.


================================================================================
RULE 10 | TRANSCRIPT REF FOR LISTENING ITEMS
================================================================================

At preparatory, listening lives WITHIN the oracy spine — there is no
separate listening spine.

A listening-based oracy item carries `transcript_ref` at the item
level:
  - Format: "p. NN"
  - Lifted verbatim from the relevant task object's `transcript_ref`
    in the section's `oracy` cell.

The transcript text is NOT inlined into the item. The generator
reads `transcript_text` for verification only (Rule 6); the teacher
reads aloud from the textbook at the indicated page.

Non-listening oracy items (free conversation, recitation, picture
discussion, etc.) carry `transcript_ref: ""`.


================================================================================
RULE 11 | RUBRIC DEPTH (OPEN ITEMS)
================================================================================

`expected_elements` at preparatory: 3 bullets, each ≤ 8 words, plain
expectations. No register critique, no literary-device requirements
— those belong to middle and secondary.


================================================================================
RULE 12 | HEADER
================================================================================

Appears once at the top of the assessment document:
  - `chapter_number`, `chapter_title`, `stage` ("preparatory"), `grade`
  - `main_sections_inventory[]` — id, title, type
  - `total_items` — count across all spines

Item bodies MUST NOT reference C-codes.


================================================================================
RULE 13 | NO INTERNAL IDS IN TEACHER PROSE
================================================================================

Internal item IDs (e.g. "Q-READ-A-1") live only in the JSON `id`
field as a join key. They MUST NEVER appear in teacher-facing prose
(stems, suggested answers, expected_elements, notes).


================================================================================
ASSESSMENT JSON SCHEMA
================================================================================

{
  "subject":        "english",
  "stage":          "preparatory",
  "grade":          string,                   // "iii" | "iv" | "v"
  "chapter_number": integer,
  "chapter_title":  string,
  "total_items":    integer,

  "main_sections_inventory": [
    { "section_id": string, "title": string, "type": string }
    // type ∈ poem | prose | narrative | dialogue | informational | picture_narrative
  ],

  "assessment_items": [
    {
      "spine_code":  string,                  // reading | oracy | writing |
                                              // word_work |
                                              // beyond_text
      "spine_title": string,                  // human-readable label
      "items": [
        {
          "id":                    string,    // e.g. "Q-READ-A-1"
          "source_section_id":     string,    // "A" | "B" | "C"
          "source_section_title":  string,
          "source_section_type":   string,    // see inventory
          "source_spine":          string,    // see spine_code
          "source_lo":             string,    // implied_lo from LP handoff
          "source_context":        string,    // section_context from LP handoff

          "item_stem":             string,    // the assessment question / task
                                              // framing; original; grounded
                                              // per Rule 3

          "question_type":         string,    // see Rule 4

          "options": [                        // MCQ and TRUE_FALSE only;
                                              // [] otherwise
            { "label":      string,           // "A"|"B"|"C"|"D" (MCQ) |
                                              // "1"…"N" (TRUE_FALSE)
              "text":       string,
              "is_correct": boolean }
          ],

          "visual_stimulus":       string,    // "" | pipe-table (Rule 9)

          "transcript_ref":        string,    // listening-based oracy only;
                                              // "" otherwise

          "teacher_guide": {
            "suggested_answer":    string,    // CLOSED (non-MCQ): verified
                                              // answer in plain prose;
                                              // "" for MCQ and OPEN types
            "expected_elements":   [string],  // OPEN only; [] otherwise
            "answer_key": [                   // MATCH only; [] otherwise
              { "left":  string,              //   Column A entry (or event)
                "right": string } ],          //   correct match (or order #)
            "what_each_option_reveals": {     // MCQ only; {} otherwise.
              "A": string, "C": string, ...   //   one entry per INCORRECT
            },                                //   option label; omit correct
            "note":                string     // empty unless verification
                                              //   fallback (Rule fallback)
          },

          "verified":              boolean
        }
      ]
    }
  ]
}
