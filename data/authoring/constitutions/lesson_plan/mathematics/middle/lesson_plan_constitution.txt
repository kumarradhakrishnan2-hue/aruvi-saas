ARUVI — MATHEMATICS LESSON PLAN CONSTITUTION · VERSION 3.9

VOCABULARY (teacher-facing naming):
The atomic teaching chunk is called a "unit" in ALL teacher-facing prose — teacher_notes, activity titles, homework, and any cross-reference to another chunk. The token "period" is retained ONLY in (a) schema field names (period_number, period_duration_minutes, periods[], etc.) and (b) the scheduling/allocation budget (period schedule, period count, per-period budget). Never write "period" in prose the teacher reads; "session" is outside the register too.
Stages: Foundational, Preparatory, Middle, Secondary

THE SELF-CONTAINED REGISTER (binds Rule 10 and teacher_notes)
Three things no time band or teacher note may do, each because the platform enforces it:
1. NAME A CLOCK QUANTITY — the platform scales every band's minutes in proportion to the sitting that carries it, so a stated number is falsified silently: no "for three minutes", "the remaining time", "half the session". Where a task is genuinely brief or genuinely long, say so in kind — "a quick mental calculation", "an extended construction" — never in number.
2. POINT FORWARD OR CLAIM COMPLETION — a teacher's plan may end, or hand over to a companion variant's unit, after any unit, so "the next unit", "as we will see", "having covered all three angle pairs" are wrong for someone. Each unit closes on its own ground.
3. NAME CALENDAR TIME — Aruvi keeps no calendar and sittings do not map to days: today, yesterday, this week, next class are unknowable at authoring.
Backward continuity is welcome, and is best carried by naming the content built on ("Having established that vertically opposite angles are equal, …" — Rule 10's continuity link) rather than a unit's position.

================================================================================
DESIGN PRINCIPLE
================================================================================

The textbook's section order is the LP's structural axis. Each section's
`section_goal` (from the summary) shapes the period's pedagogy.
Competencies are informational only.

The LP references textbook items by their `book_ref` (the teacher-facing
locator: banner + question number + page). It does NOT reprint item
content. Internal IDs (`A-N`, `WE-N`, `E-N`) live only in JSON
structured fields as join keys for downstream assessment routing —
they MUST NEVER appear in any prose the teacher reads.


================================================================================
INPUTS
================================================================================

1. Mapping JSON (core_cg, competencies, dissolution_test, effort signals).
2. Summary JSON (sections with `section_goal` array, prose, enumerated
   items each carrying `id`, `source_section`, `book_ref`, `description`).
3. Stage-appropriate NCF Pedagogy document (source of the five permitted
   methods).
4. Period schedule — exactly ONE row {duration_minutes, count}: the
   class-standard duration (40 min for classes up to VII, 45 for VIII,
   50 for IX–X — the master-plan calibration bands, not NCF's flat 40)
   × the period count; total = B. Teacher timetable variation never
   reaches generation; it is handled downstream at serve time.


================================================================================
OUTPUT
================================================================================

LP JSON per chapter: header, periods array, coverage_handoff block.


================================================================================
RULE 1 | SECTION ANCHORING
================================================================================

LP walks textbook section order. Do NOT reorder, interleave, or
re-sequence. A period anchors to as many ADJACENT sections as its
content warrants.

A section's periods are CONTIGUOUS. Once the plan has moved past a
section it does not return: a later period MUST NOT re-anchor a section
an earlier run already completed. Consolidation and extended practice
belong INSIDE that section's own run, where the class is still working
on it — never as a revisit after other sections have been taught.


================================================================================
RULE 2 | FULL-SECTION COVERAGE
================================================================================

Allocate exactly B periods across sections, in section order.

- Every section listed in the summary MUST appear in at least one
  period's `textbook_segments`. Dropping a section is FORBIDDEN —
  including consolidation-only sections (e.g., "Parallel Illusions"
  closing §s).
- A section MAY span as many ADJACENT periods as its content warrants.
  Emphasis follows the SUBSTANCE of the section — the number of
  enumerated items, the demand of the implied task — never the
  effort_index, which governs only how the chapter as a whole is
  allotted time in the Allocate step, never how periods are
  distributed within it.
- Light sections MAY merge with an adjacent section.

PROHIBITION
1. MUST NOT apply any numerical allocation formula across sections
   within the chapter.
2. MUST NOT front-load the plan by exhausting early sections and
   compressing or skipping later ones.

When a section's summary `section_goal` is a two-element array, the
LP MAY split that section's run so the EARLIER periods of the run
carry the first-listed goal and the LATER periods the second, in
textbook order.

The LP MUST NOT split a single-goal section across two different
goals. If a heavy single-goal section spans several periods, every
period of that run carries the same `section_goal`.


================================================================================
RULE 3 | ITEM SOURCING — CHAPTER ONLY · STRICT ID MATCH
================================================================================

Every enumerated item in the LP is a pointer to a summary enumeration.
No fabrication. Period concepts are drawn from the summary's prose for
the anchored section(s).

Internal IDs (`id` field) MUST equal exactly an `id` present in the
summary's `enumerated_activities`, `enumerated_worked_examples`, or
`enumerated_exercises` arrays.

FORBIDDEN:
- Inventing IDs (e.g., `WE-1a`, `GA-1a`, `ICP-1a`, `HW-1`).
- Adding `-a` / `-b` suffixes to split a summary item across periods.
- Substituting a "guided activity" or "in-class practice" ID prefix
  for a summary item that is enumerated as an activity, worked example,
  or exercise.

If a single summary item is referenced by multiple periods (legitimate
for items that span sub-arcs), each period lists the same single ID.


================================================================================
RULE 4 | GOAL CONFORMANCE
================================================================================

Each period's `section_goal` MUST equal one of the goals declared by
the summary for that period's anchored section(s).

The LP MUST NOT introduce a goal not present in the summary's section
entry. If the summary's tagging is wrong for a section, fix the
summary — do NOT override at LP generation time.

When a period anchors to two adjacent sections, the period's
`section_goal` MUST be a goal declared by at least one of those
sections.


================================================================================
RULE 5 | PEDAGOGICAL METHOD
================================================================================

One method per period, from: Discovery · Problem-solving · Play-way ·
Inductive · Deductive.

Default mapping from `section_goal`:

  recall  → Discovery, Inductive
  reason  → Deductive, Inductive
  apply   → Problem-solving, Play-way

Diversity: same method SHOULD NOT appear in more than two consecutive
periods. Each method SHOULD appear at least once per chapter where
content permits.

The cap YIELDS where the anchored sections genuinely converge on one
kind of work — most often at a chapter's tail, where extended practice,
contextual application and a closing synthesis are all honestly
problem-solving. Where it yields, the method named is the one the
content supports; a run produced for convenience, or to avoid thinking
about pedagogy, remains forbidden. The default mapping above still
binds, and a chapter whose every period carries one method is a defect,
not an exception.


================================================================================
RULE 6 | TIME CONSTRAINT
================================================================================

Each period's time bands sum exactly to `period_duration_minutes`.
Minimum 3 time bands per period.

`time_bands[].minutes` is a STRING time-range (e.g., `"0–10"`,
`"10–25"`). Ranges tile the period from `0` to
`period_duration_minutes` with no gaps and no overlaps.

Overrun is not permitted.


================================================================================
RULE 7 | CHAPTER HEADER TABLE (INFORMATIONAL)
================================================================================

Appears once at the top of the LP document:
- chapter_number, chapter_title
- core_cg
- core_competencies (c_code + text)
- adjunct_competencies (c_code + text)
- periods_allocated (= B)


================================================================================
RULE 8 | COMPETENCIES DO NOT DRIVE LP
================================================================================

Periods are not required to cover specific competencies. LP body text
MUST NOT reference C-codes. Competencies appear only in the header
table and in mapping/audit JSON, never in periods, time bands, or
teacher_notes.


================================================================================
RULE 9 | HOMEWORK IS OPTIONAL AND UN-OWNED
================================================================================

`homework` per period is `[]` by default. Populate with 1–2 items only
when in-class time-box overflows or the generator judges reinforcement
useful. Homework is not consumed by the assessment generator
downstream.


================================================================================
RULE 10 | TIME-BAND NARRATION USES book_ref, NOT INTERNAL ID
================================================================================

When a time band invokes a textbook item, the band's `activity` text
names the item by its `book_ref` (e.g., `"Activity 1 (p.105)"`,
`"Figure it Out Q1 (p.107)"`, `"Example 3 (§5.8 p.122)"`), followed
immediately by the item's `description` in brackets and inverted commas,
limited to 10 words at most with `....` appended if truncated.

Format: book_ref (“description up to 10 words....”)
Example: Activity 1 (p.107) (“draw two lines on a plain sheet that intersect....”)

Use the CURLY quotation marks shown (“ ”), never straight double
quotes. The plan is emitted as JSON, where a straight " inside a string value must
be escaped; an unescaped one ends the string early and destroys the file. Curly
marks need no escaping and read better in print. (Plans authored before this
version used straight quotes here; that form remains valid and is not a defect.)

Do not use prose to describe the textbook item.

Every band is additionally bound by THE SELF-CONTAINED REGISTER: it
names no clock quantity, points forward at nothing, claims no
completion, and names no calendar time. Each band speaks in the present
of its own activity; unit-to-unit linking lives only in teacher_notes.

The band's `activity` text MUST NOT use the internal `id` (e.g., `A-1`,
`WE-3`, `E-9`). Internal IDs live only inside the structured
`textbook_items_in_class[]` and `homework[]` arrays as join keys.


================================================================================
RULE 11 | COVERAGE HANDOFF EMISSION
================================================================================

After period assignment, emit `coverage_handoff` — three clusters
keyed to `section_goal`:

  section_a (Recall and Apply)     ← recall
  section_b (Reason and Explain)   ← reason
  section_c (Apply in Context)     ← apply

ONE HANDOFF ENTRY PER PERIOD. Each period in the LP contributes
exactly one entry, routed to the cluster matching the period's
`section_goal`:

  section_goal == "recall"  →  section_a.goals
  section_goal == "reason"  →  section_b.goals
  section_goal == "apply"   →  section_c.goals

Total assessment item count = number of periods (one item per goal,
one goal per period). This scales the assessment with chapter depth
even when a chapter has only a few textbook sections.

Within each cluster, entries appear in period order (period 1 first,
then period 2, and so on, skipping periods routed to other clusters).

Each entry:

- `section_ref`       — the period's primary anchored section. When
                        the period anchors to two adjacent sections
                        (Rule 1), the primary section is the one
                        whose summary declares the period's
                        `section_goal`. When both anchored sections
                        declare that goal, use the first (lower-
                        numbered) section.
- `section_title`     — title of `section_ref`, copied verbatim from
                        the summary's `sections[i].title`. Threaded
                        through so the assessment renderer can show
                        section name without re-reading the summary.
- `goal`              — the period's `section_goal` value (`recall`
                        | `reason` | `apply`).
- `anchor_id`         — id of one summary item drawn from the
                        period's own `textbook_items_in_class[]`
                        first, falling through to the period's
                        `homework[]` if the in-class pool yields no
                        un-used candidate. Within each pool, walk
                        in array order and apply type priority:
                        `exercise` (E-N) → `worked_example` (WE-N)
                        → `activity` (A-N).
- `anchor_book_ref`   — `book_ref` of `anchor_id`, copied from the
                        period entry. Empty string when the period's
                        pools yield no anchor (see below).
- `anchor_description` — `description` of `anchor_id`, copied from
                        the period entry. Empty string when the
                        period's pools yield no anchor (see below).

Anchor selection (per period).

1. From the period's `textbook_items_in_class[]`, walk array order
   and pick the first item whose id has NOT yet been used as an
   `anchor_id` by an earlier handoff entry, applying type priority
   exercise → worked_example → activity within that array.
2. If step 1 yields nothing, fall through to the period's
   `homework[]` and apply the same logic.
3. If both pools yield nothing un-used, the entry MAY reuse an id
   already used by an earlier entry (uniqueness across the handoff
   is best-effort, not absolute, since the handoff now has as many
   entries as periods and per-period pools may be small).
4. If the period's `textbook_items_in_class[]` AND `homework[]` are
   both empty (a guard case — Rule 6 time bands normally require
   textbook items), set `anchor_id = ""`, `anchor_book_ref = ""`,
   `anchor_description = ""`. The assessment generator omits the
   exercise companion in this case but still generates a typed
   question grounded in the section's prose.

If a cluster receives no entries (no period's `section_goal` routes
to it), emit the cluster with an empty `goals` array. The assessment
generator emits no items for an empty cluster.

LP JSON SCHEMA
================================================================================

{
  "chapter_number": integer,
  "chapter_title":  string,
  "core_cg":        string,
  "core_competencies":    [ { "c_code", "competency_text" } ],
  "adjunct_competencies": [ { "c_code", "competency_text" } ],

  "dissolution_test":     string,

  "lesson_plan": { "periods": [ <period>, ... ] },

  "coverage_handoff": {
    "section_a": { "goal_cluster": ["recall"],
                   "goals": [
                     { "section_ref":         string, // e.g. "§5.1"

                       "goal":                "recall",

                       "anchor_description":  string  // verbatim from summary entry (or "")
                     }
                   ] },
    "section_b": { "goal_cluster": ["reason"], "goals": [ ... ] },
    "section_c": { "goal_cluster": ["apply"],  "goals": [ ... ] }
  }
}
