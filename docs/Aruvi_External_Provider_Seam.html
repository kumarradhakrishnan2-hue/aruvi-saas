ARUVI'S OWN CODE — RETAINED, NOT REBUILT
Answers Section 3 of the Technology Partnership & Production Roadmap: what can be retained, and what must be replaced.
web/ Next.js
The teacher-facing app. Mobile-first and responsive. Speaks HTTP to the API and to nothing else.
api/ FastAPI service
The service layer. Every provider in the product is chosen in ONE block: main.py, lines 79–227.
aruvi_core/ the engine
Lesson generation, period allocation, canonical view model, five subject plugins. Pure Python, no UI.
genon/ authoring pipeline
Runs offline to build the lesson library. Not part of the live service, and not part of the handover. Unrelated to aruvi_core/genon/, which is the live serve engine.
No vendor name appears anywhere above this line.
aruvi_core/ports.py — 22 named interfaces
The engine depends on these and never on a provider. Swapping a vendor is one new adapter class plus one line in api/main.py. Every one of the 22 is now honoured — no caller reaches past a port.

Config, not code
Every provider setting is an environment variable in api/config.py. No secret is committed to the repository.
The contracts are tested
43 test files exercise the ports — including one that runs the runtime against a store with no filesystem at all — so a swapped adapter is verifiable rather than hopeful.
Ownership
Cloud, database, domain, store and gateway accounts to be created in Aruvi's own name. The partner receives access, not ownership.
